# 🧪 Agentarium

> **A growing ecosystem of AI agents, skills, and workflows for the craft of building software.**

Welcome to **Agentarium** — my personal collection of AI agents, reusable skills, and development workflows that help me think, build, debug, and learn as a software engineer.

Think of it as a little ecosystem of specialized helpers, each with its own purpose, knowledge, and abilities. Some help design systems, some review code, some hunt bugs, and others help me learn something new.

As I grow as an engineer, so does the Agentarium.

## 🧬 What's Inside?

| Directory | Description |
| --- | --- |
| `agents/` | Specialized AI agents with defined roles, responsibilities, and instructions. |
| `prompts/` | Reusable prompt templates. |
| `skills/` | Reusable knowledge and procedures for specific technologies, tools, and engineering tasks. |
| `workflows/` | Repeatable processes for tackling common development tasks. |
| `templates/` | Starting points for creating new agents, skills, and workflows. |

The structure may evolve as the ecosystem grows.

## 🛠️ Philosophy

Agentarium isn't about collecting agents for the sake of collecting them. It's about building a toolkit that becomes more useful over time.

- **Reusable by design.** Write instructions once, use them across projects.
- **Small, specialized, composable.** Give each agent or skill a clear purpose and combine them when needed.
- **Grounded in real work.** Improve them through practical experience, mistakes, and lessons learned.
- **Tool-agnostic where possible.** Keep knowledge portable and avoid unnecessary dependence on a single AI coding tool.
- **Always evolving.** Refine existing capabilities, retire what no longer works, and introduce new ones as needed.

## 🧑‍🔬 Adding to the Ecosystem

Every new addition should solve a real problem or make an existing task easier.

When creating an agent or skill, aim for:

1. **A clear purpose** — What problem does it solve?
2. **Explicit instructions** — What should it do, and what should it avoid?
3. **Useful context** — What knowledge, tools, or references does it need?
4. **Practical output** — What should its results look like?
5. **Room for improvement** — How can it be tested and refined?

Prefer a small, reliable collection of useful tools over a large collection of redundant ones.

## 🌱 The Bigger Picture

Software engineering is a journey of continuous learning. Agentarium is where I turn that learning into reusable capabilities — capturing knowledge, refining processes, and building better ways to work.

Today, it might help me write better Go code or design a system. Tomorrow, it might help me investigate a security issue, review an architecture, or explore an unfamiliar technology.

**One ecosystem. Many capabilities. Always evolving.**
